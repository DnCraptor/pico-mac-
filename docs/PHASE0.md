# Фаза 0 — базовая конфигурация, референс и измерения

Фиксирует разработочную конфигурацию, запиненный референс и методику измерения
скорости эмуляции. Числа вписываются в таблицы по мере снятия на железе.

## 1. Разработочная конфигурация: родное 512×342, малое ОЗУ

* Разрешение — **родное 512×342** (`USE_VGA_RES=0`, `DISP_WIDTH=512`,
  `DISP_HEIGHT=342`), используется ПЗУ `umac-rom-208-orig.h`. Режим 640×480
  не полностью поддерживается ПО Mac; на родном разрешении баги эмулятора не
  путаются с неполной поддержкой нестандартных режимов. VGA-драйвер центрирует
  512×342 внутри сигнала 640×480 (бордюры 64px по бокам, 69 строк сверху/снизу).
  Для родного размера `umac_get_fb_offset()` даёт `RAM_SIZE - 0x5900` — штатное
  расположение экранного буфера Mac.
* ОЗУ Mac — малое, чтобы запас SRAM не мешал (итог подбирается в Фазе 7).
  Опция `DEV_SMALL_RAM` (по умолчанию `ON`) → `UMAC_MEMSIZE=208`.
  `OFF` → `UMAC_MEMSIZE=464` (релизный размер).

Про 128 КБ: это «штатный» размер, но готового `umac-rom-128-orig.h` в
репозитории нет — нужно один раз сгенерировать инструментом `umac_rom_patch`
(`UMAC_MEMSIZE=128`) и добавить ветку `#if UMAC_MEMSIZE==128` в `src/main.cpp`.
До тех пор dev-базой служит 208 КБ.

## 2. Бенчмарк скорости эмуляции (вывод на экран)

UART на целевых платах недоступен, поэтому результат рисуется **прямо в
кадровый буфер Mac** — маленький HUD в левом верхнем углу (белый текст на
чёрном боксе, обновление ~30 Гц).

### Что меряется

`global_time_us` в ядре umac растёт ровно на один `UMAC_EXECLOOP_QUANTUM` за
каждый `umac_loop()`, независимо от реального времени. Отношение
«эмулированное/реальное время» — прямая мера запаса:

* `speed = 1.000` — ровно реальное время (настоящий 68000 @ 7.8336 МГц);
* `speed > 1` — есть запас; `speed < 1` — медленнее реального Mac.

Эффективная частота m68k = `7.8336 МГц * speed`.

### HUD (две строки)

```
S1.842X Q46 C378     speed (× реального времени), quantum (µs), CPU (МГц)
M14.4                эффективная частота m68k (МГц)
```

### Как собрать

Бенчмарк включён в `CMakeLists.txt` строкой `set(BENCH_EMU ON)` (рядом с
`set(KBDUSB ON)`) — отдельный флаг не нужен, обычная сборка вашим пресетом
даёт HUD. Признак, что собран нужный вариант: имя `.elf` содержит суффикс
**`-BENCH`** (напр. `...-VGA-0.0.8-BENCH.elf`). Чтобы выключить — закомментируйте
`set(BENCH_EMU ON)`.

Прошить `.uf2`, смотреть HUD на экране (плюс тонкая рамка по краю кадра —
маркер активного бенча). USB-ввод работает; UART не используется.

### Что снять

Сравнить влияние кванта и частоты — пересобрать под каждую строку таблицы.

* Квант: `external/umac/src/main.c`, `#define UMAC_EXECLOOP_QUANTUM`
  (в этой ветке = 46; для сравнения поставить 5000).
* Частота: `set(CPU_MHZ ...)` в `CMakeLists.txt`.

## 3. Результаты (Murmulator 1.x / pico2, 378 МГц, ОЗУ 208 КБ, родное 512×342)

Метрика HUD: `S` — множитель к реальному времени, `M` — эффективная частота
m68k (МГц). `DEFAULT_THROTTLING=0` (троттлинга нет), поэтому `S` — это потолок.

| quantum, µs | idle (S / M) | LoadRunner (S / M) |
|-------------|--------------|--------------------|
| 46          | 1.024 / 8.0  | 2.506 / 20.0       |
| 5000        | 1.276 / 9.9  | 3.299 / 25.4       |

Вывод: квант 5000 быстрее кванта 46 на **+24.6 % в простое** и **+31.6 % под
нагрузкой** (LoadRunner); т.е. квант 46 отъедает ~20–24 % производительности.
При кванте 46 простой идёт лишь 1.024× — почти впритык к реальному времени
(риск для звука в Фазе 4). При 5000 в простое 1.276× — есть запас.

Замечание: `S` растёт под нагрузкой и падает в простое, потому что холостой
цикл Mac упирается в эмуляцию обращений к I/O (VIA), а не в такты ЦП; это
особенность umac, к кванту отношения не имеет.

**Решение для Фазы 1:** вернуть большой квант (≈5000). Точность T1 для звука
добирать в Фазе 4 «догоняющим» `while` в `via_tick` и/или развязкой T1 от
кванта (чтение сэмплов в PWM/HDMI уже идёт от реального таймера), а не
измельчением глобального кванта.

## 4. Отчёт по памяти (`--print-memory-usage`)

Индикатор запаса SRAM для dev-конфига (не ограничение; итог — Фаза 7).

| Конфиг | ОЗУ Mac | Занято RAM | Регион | %  |
|--------|---------|------------|--------|----|
| dev (DEV_SMALL_RAM=ON) | 208 КБ | 234820 B | 512 KB | 44.79% |
| release (OFF)          | 464 КБ |          | 512 KB |        |

Замер dev-сборки (snd, 378 МГц, VGA, 0.0.8): RAM 44.79%, SCRATCH_X 79.3%,
SCRATCH_Y 50%, FLASH 27.66% — запас большой (~277 КБ SRAM свободно).

## 5. Baseline поведения

* Видео: OK — System грузится до рабочего стола (родное 512×342), приложения
  запускаются (LoadRunner). HUD-оверлей рисуется поверх кадра.
* Ввод: USB-мышь работает (перетаскивание влияет на нагрузку/скорость).
  Полная сверка (клавиатура/NES/XInput) — Фаза 1b.
* Звук: (snd) — отдельно, Фаза 4.

## 6. Референс: пин

Драйверы (libdvi, tv, ps2kbd, nespad, usb, graphics) портируются из
**зафиксированного** коммита emu80, чтобы не переносить уже исправленные баги.

* Репозиторий: `DnCraptor/emu80v4`, ветка `vector06c`
* Пин-коммит: **`760330a`** (v0.6.2, «TV RGB»)

Обязательные фиксы — в корневом `PLAN.md`, §7 (в т.ч. `libdvi/dvi.c` — HDMI
aux-пакеты в back porch; `RGB_TV`; Korver-правка `tusb_config.h`; маппинг
джойстиков; плата `pimoroni-pico-dv` с I²S ЦАП PCM5100A).
